## Overview

The current data model lives in `omnir-go-backend/db/migrations/` (goose SQL) and `internal/domain/` (Go structs). Five core entities are defined and implemented.

### 4. `pipelines`

| Column     | Type        | Notes                                         |
|------------|-------------|-----------------------------------------------|
| id         | UUID PK     |                                               |

No Go domain struct yet — stages are embedded in deal handling.

## Relationship Diagram

```
users
  ├── owns → accounts (owner_id)
  ├── owns → contacts (owner_id)
  └── owns → deals (owner_id)

accounts
  └── has many → contacts (account_id)
  └── has many → deals (account_id)

contacts
  └── has many → deals (contact_id)

pipelines
  └── has many → deals (pipeline_id)
```

## What's Missing / Gaps to Address

1. **Activities** — No calls, emails, meetings, tasks table. Critical for CRM workflows.
2. **Notes** — No notes/comments on contacts/deals.
3. **deal_contacts junction** — Deals can only link to one contact. vtiger supports many-to-many.
4. **Pipeline domain struct** — Pipeline has no Go domain type; stages live as raw JSONB.
5. **users.password_hash** — Auth fields not in schema (presumably handled externally via JWT, but needs verification).
6. **Multi-tenancy** — No `org_id` / workspace isolation. Fine for v1, needs planning for SaaS.
7. **Audit log** — No change history tracking on any entity.
