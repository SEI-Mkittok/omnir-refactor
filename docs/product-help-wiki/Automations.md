# Automations

Automations reduce repeated manual work by reacting to events or scheduled conditions.

## Good Automation Candidates

Automate work that is:

- Repetitive.
- Rule-based.
- Low-risk.
- Easy to verify.

Examples:

- Notify a team when a high-priority ticket is created.
- Create a follow-up task after a deal stage change.
- Send a reminder when a record has no owner.
- Trigger a webhook for an external workflow.

## Poor Automation Candidates

Avoid automating decisions that need human judgment, such as:

- Complex prioritization.
- Sensitive customer communication.
- Large destructive updates.
- Ambiguous assignment rules.

## Building Safely

Before enabling an automation:

1. Name it clearly.
2. Confirm the trigger.
3. Confirm the action.
4. Test with a small scenario.
5. Watch the first real runs.

## Ownership

Every automation should have an owner. If nobody owns it, it will eventually become confusing or risky.
