# Settings and Customization

Omnir can be customized, but customization should support real workflow needs.

## Company Profile

Use Company Profile for organization identity, website, address, and contact details.

## Custom Fields

Create custom fields when standard fields do not capture required information.

Good custom fields are:

- Clearly named.
- Used by a real process.
- Reportable.
- Maintained by users.

Avoid custom fields that duplicate existing fields or capture notes that belong in comments.

## Module Layouts

Module layouts control how fields appear in record forms and pages.

Put frequently used fields near the top. Hide rarely used fields if they distract from daily work.

## Picklists and Dependencies

Picklists make data cleaner by limiting choices. Dependencies can constrain one picklist based on another.

Review picklists periodically. Old values create bad reporting.

## Document Numbering

Configure prefixes and starting numbers before launch for:

- Quotes
- Tickets
- Invoices
- Tenant KB articles

Changing numbering after users and customers see records can cause confusion.

## Best Practice

Customize slowly. Every field, layout, and picklist becomes part of the team's operating language.
