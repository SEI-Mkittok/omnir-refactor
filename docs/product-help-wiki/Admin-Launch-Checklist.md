# Admin Launch Checklist

Use this checklist before inviting the full team into a new Omnir workspace.

## Workspace Identity

- Company name is correct.
- Logo, website, phone, and address are complete where needed.
- Support email is set in configuration.
- Default page size and preview lengths are reasonable.

## Users and Access

- Admin users are limited to people who need admin rights.
- Agent and manager profiles match your operating model.
- Sharing rules match your privacy expectations.
- Groups exist for teams that need shared record access.
- Two-factor authentication expectations are communicated.

## CRM Structure

- Required custom fields are truly required.
- Picklists use clear labels and avoid duplicate meanings.
- Module layouts show the fields users need most often.
- Document numbering prefixes match your naming conventions.

## Service Setup

- Ticket priorities and statuses are understood by the team.
- SLA policies are configured if response or resolution commitments matter.
- Portal configuration is reviewed before being shared with customers.
- Tenant Knowledge Base categories are created if customers will self-serve.

## Integrations

- Email and calendar OAuth settings are configured.
- Outgoing email settings are tested.
- Webhooks are created only for approved endpoints.
- API keys are scoped to the systems that need them.

## Launch Review

Invite a small pilot group first. Ask them to run real workflows for one or two days, then adjust settings before inviting the rest of the organization.
