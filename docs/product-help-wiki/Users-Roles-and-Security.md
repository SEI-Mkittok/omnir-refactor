# Users, Roles, and Security

Admins control who can access Omnir and what they can do.

## Users

Create users for internal team members who need CRM access.

Before inviting a user, decide:

- What role they should have.
- Which profile or permissions they need.
- Whether they need admin access.
- Which team or group they belong to.

## Roles

Roles describe hierarchy and ownership patterns. They help determine visibility and responsibility.

Use roles to model the organization, not every temporary project.

## Profiles

Profiles define module permissions and field write access.

Use profiles to answer:

- Can this user read this module?
- Can this user create or update records?
- Can this user administer settings?
- Can this user edit sensitive fields?

## Sharing Rules and Groups

Sharing rules define record visibility defaults and exceptions. Groups make it easier to grant access to a set of users.

Review sharing whenever the team structure changes.

## Security Basics

- Keep admin access limited.
- Use two-factor authentication where appropriate.
- Rotate API keys when ownership changes.
- Remove inactive users promptly.
- Do not share accounts.
