# Original CRM Screenshot Function Index

Source folder: `docs/screenshots_original_UIUX`

The screenshots are indexed in timestamp order by filename. This document captures the legacy CRM feature/function surface represented by each screenshot so the refactor can preserve the important workflows while replacing the UI. It intentionally documents capabilities, not final visual direction; use [ux-spec.md](ux-spec.md) for the modern UI language.

Sensitive record values visible inside screenshots are not transcribed here. The index focuses on functions and workflow coverage.

## Coverage Map

- Core navigation: dashboard, marketing, sales, inventory, support, projects, tools, mail manager, documents, extension store, settings.
- CRM modules: campaigns, leads, contacts, organizations, opportunities, quotes, products, services, tickets, assets, projects, tasks, milestones, invoices, orders, vendors, documents.
- Admin and security: users, roles, profiles, sharing rules, groups, login history.
- Customization: module enablement, layouts and fields, relationships, duplicate prevention, numbering, picklists, picklist dependencies, main menu configuration.
- Automation and intake: webforms, scheduler jobs, workflow rules, mail converter.
- Business configuration: company details, customer portal, outgoing SMTP server, global configuration values, tax calculations, terms and conditions, calendar settings.
- Mapping rules: lead conversion data mapping and opportunity-to-project mapping.

## Functional Takeaways

- The legacy CRM is module-first, with the same entities appearing under multiple business areas. The modern navigation can simplify this, but it should preserve cross-module access to Contacts, Organizations, Products, Services, and Documents.
- Admin capabilities are broad enough to require a real settings console, not just static app configuration. The minimum functional set is RBAC, sharing rules, groups, layouts/fields, numbering, picklists, menu configuration, scheduler visibility, workflow rules, webforms, SMTP, customer portal, tax, terms, and calendar preferences.
- Automation is a first-class CRM feature: webforms capture external records, scheduler jobs run platform tasks, workflows trigger emails/functions, and mail converter turns inbox activity into CRM records.
- The screenshots include configuration data that should be modeled separately from tenant business records: company profile, portal settings, outbound mail settings, global limits, tax rules, terms templates, and personal calendar preferences.
- Mapping screens imply important conversion contracts: Leads convert into Organizations, Contacts, and Opportunities; Opportunities can generate Projects.
